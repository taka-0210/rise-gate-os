# 計画・提案・実績の保存方針

RISE GATE OSでは、計画を固定された正解ではなく、実行前の仮説として扱う。

## 保存する4つの情報

1. 現在計画
   - 現在採用されているロードマップ、取り組み、タスク。
2. 計画版
   - 提案を承認した時点の計画全体のスナップショット。
   - 過去の版は上書きしない。
3. 提案
   - 誰が、いつ、何を、なぜ変えようとしたか。
   - 検証エラー、却下、再提案も履歴として残す。
4. 実績
   - 実際に行った作業、工数、開始・完了日時、成果。
   - 当初計画に存在しなかった作業も記録できる。

## 承認時の処理

1. 承認直前の現在計画を取得する。
2. 提案内容を現在計画へ反映する。
3. 反映後の計画を新しい計画版として保存する。
4. 提案と生成した計画版を関連付ける。
5. 提案自体と提案項目は変更しない。

## 再計画

再計画では、当初計画より実績を優先する。

1. 実装・作業の完了実績を整理する。
2. 当初になかった追加作業を実績として補完する。
3. 残作業を定義する。
4. 工数を再集計する。
5. 最後に期間とガントチャートを引き直す。

期間整合性は重要だが、実績の記録を拒否する理由にはしない。実績を保存したうえで、期間の不整合は再計画が必要な警告として扱う。

## データ構造

- `ai_proposals`, `ai_proposal_items`: 提案時点の不変履歴
- `project_plan_versions`: 承認によって生成された計画版
- `project_actuals`: 計画から独立した実績
- `projects`, `roadmaps`, `improvements`, `tasks`: 現在計画
