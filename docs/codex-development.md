# 3ペインのCodex開発

## 利用方法

1. 最新の開発用ZIPを通常のフォルダへ展開してセットアップを実行する。
2. 3ペインのFILESで「開発ツール」を開き、PC側ツールへ接続して保存フォルダを選ぶ。
3. 「Codexで開発」から右側の開発画面を開き、「Codexに接続」を押す。
4. PCのCodexに認証があれば利用する。なければChatGPTでログインするか、OpenAI APIキーをPC側Codexへ登録する。
5. 開発内容を送る。Codexが必要なファイルを読み、直接編集して実行・テストする。
6. 操作承認が表示された場合はコマンド・変更内容を確認して許可／拒否する。「作業を停止」で中断する。
7. ファイル作成後、FILESの「起動」でPHPアプリを確認する。通常の会話へ戻るには「会話・資料作成に戻る」を押す。

Codexの認証・課金はOSのAIポイントとは別。APIキーはPCへの接続でのみ送信し、OSのサーバー・AI会話・URLには含めない。管理者が会社のAPI利用を管理する場合も、OS側のキーを自動転用しない。

## 構成

- 公式Codex app-serverのstdio JSONLをPHPヘルパーから利用。公開WebSocketは使用しない。
- Codexは指定した作業フォルダでworkspace-write、on-request、ユーザー承認を使用。無制限実行には切り替えない。
- ブラウザは既存の接続コード・Origin検証・workspace指紋によるローカルAPIで進捗を取得する。
- 開発依頼はOSのLaravel/OpenAIチャット経路を通さず、PCのCodexへ送る。Codexは必要に応じてモデル提供元へコードを送信する。
- プロジェクトとフォルダごとにCodexスレッドを分離。履歴は開発ツールのローカル状態領域とCodex側に保存し、公開ZIPには入れない。
- 通常のAIパートナーは従来のAPIを利用する。開発ツール接続中のフォルダ内容を自動添付しない。
- 実行時刻・会話表示はJST。PHPのPATHは起動用スクリプトで設定する。
- OS画面の再読み込み後は「Codexに接続」で進行中の会話を取得できる。PCツール再起動後は保存済みスレッドをresumeする。停止した依頼は勝手に再送しない。

## 制約と検証

- 通常AI・Codexともにスクショを3枚まで選択・貼り付け可能。PNG/JPEG/WebP、1枚5MiB、合計10MiB。送信前にプレビュー・個別削除でき、失敗時は添付を保持する。
- Codexの画像送信にはPCツール2.1.0が必要。画像はdata URLのimage入力としてCodexへ送る。PCのOS用会話履歴にはファイル名だけを残し、画像本体は含めない。画像生成は通常AI側。
- 通常AIは画像を非公開ストレージへ保存する。先頭画像は従来の列、2枚目以降はadditional_images列で管理し、すべて本人の会話権限で配信する。デプロイ時に追加マイグレーションが必要。
- 起動後の中央プレビューは全幅・PC1280px・タブレット768px・スマホ390px、任意幅280〜2560pxに切替可能。iframeの実幅を変えるためCSSメディアクエリが反映される。ペインより広い場合は横スクロール。実機のタッチ操作や端末固有の挙動を再現する機能ではない。
- ファイル直接編集は既存のHTML変更提案カードと別経路。公開・Git pushは自動では行わない。
- 「会話・資料作成に戻る」は表示切替。実行中のCodexは停止ボタンを押すまで続く。
- Codex未導入ならセットアップが公式0.153.0のWindows x64パッケージを取得し、固定SHA-256を確認して展開する。既存CLI/VS Code版があればそちらを利用する。
- app-serverの仕様に依存するためバージョン更新時は初期化・スレッド・承認APIを再検証する。
- テストは模擬app-serverで承認、再開、中断、冪等性、JSTを検証。実Codexでは初期化・認証状態取得までを確認し、課金される生成は自動テストで行わない。
更新時は作業完了後、左側の開発ツールで「接続を解除」してから最新セットアップを実行する。待機中の旧ツールはセットアップが終了し、新版を起動する。アプリ・Codexが接続中の場合は更新を中止し、解除を案内する。通常AIの合計10MiB添付に対して、サーバーのpost_max_sizeは添付とフォームを収める値（例16M以上）、upload_max_filesizeは5M以上が必要。サーバー管理の.user.iniは変更しない。
